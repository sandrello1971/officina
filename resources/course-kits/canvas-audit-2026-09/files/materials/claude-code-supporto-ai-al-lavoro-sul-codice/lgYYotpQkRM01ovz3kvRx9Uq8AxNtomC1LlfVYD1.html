CLAUDE.md
1# Officina — piattaforma didattica (monorepo Laravel)

2Laravel 11 + Inertia/React. Postgres. Coda su Redis.
3Multi-tenant (stancl/tenancy, DB-per-tenant).

4## Setup locale
5composer install
6cp .env.example .env && php artisan key:generate
7php artisan migrate --seed
8npm install && npm run dev

9## ATTENZIONE: deploy in prod NON usa git
10Prod è su rsync manuale, non su pull. Script: deploy/prod.sh
11Escludi sempre bootstrap/cache e il servizio videoai/
12(un rsync completo di questi ha causato un 500 il 2026-06).

13## ATTENZIONE: config:cache in deploy
14Non lanciare artisan config:cache con env di test esportate
15in shell (SESSION_DRIVER, CACHE_STORE, ANTHROPIC_API_KEY=dummy):
16finiscono congelate in prod e rompono login/cache/AI.
17Usa sempre deploy/prod.sh, non i comandi a mano.

18## Struttura
19app/Services/        logica di dominio (no logica nei controller)
20app/Http/Controllers/Api/V1/   API versionata, non toccare v1 legacy
21database/migrations/  MAI modificare una migration già in prod

22## Test e verifica
23php artisan test --testsuite=Feature   (604 test, ~90s)
24Prima di ogni PR: php artisan test && npm run lint

25## Segreti
26Mai in questo file. Vivono in .env (locale) o nel vault
27del deploy (vedi docs/deploy.md).

Perché è fatto bene

1Gotcha reali, con data e causa. "rsync completo ha causato un 500 il 2026-06" trasmette un'esperienza già pagata dal team, non una regola astratta.Perché conta: un incidente raccontato con contesto viene rispettato molto più di un "fai attenzione" generico.
2Comandi copiabili e verificati. Ogni riga sotto "Setup" e "Test" è un comando che funziona così com'è, non una traccia da adattare.Perché conta: l'agente esegue senza dover indovinare varianti, e il file resta verificabile da chiunque lo legga.
3Percorsi reali del repo. Cartelle e file nominati esplicitamente (deploy/prod.sh, app/Services/) trasformano il file in una mappa, non in una descrizione.Perché conta: l'agente parte già orientato invece di dover esplorare la struttura da zero a ogni sessione.
4Nessun segreto — solo il puntatore. Il file dice dove vivono le credenziali, non quali sono.Perché conta: CLAUDE.md finisce nel repo e viene letto a ogni sessione — deve poter essere condiviso senza rischio.
5Regole con un motivo, non un'esortazione. "Mai modificare una migration già in prod" spiega una conseguenza operativa, non un principio da manuale.Perché conta: una regola con la sua ragione resiste anche ai casi limite non previsti esplicitamente.
CriterioIn questo esempio
ComandiCopiabili e verificati, non varianti da indovinare
Gotcha di prodDocumentati con data e causa dell'incidente
PercorsiCartelle e file reali del repo
SegretiSolo puntatore a dove vivono, mai il valore
Tono delle regoleCausale ("perché ha rotto X il giorno Y")
LunghezzaSezioni brevi, scremabili in 30 secondi
Da portare in aula: CLAUDE.md non va scritto una volta e dimenticato. Ogni volta che un incidente di deploy o un bug ricorrente viene risolto, quella lezione appartiene al file — catturare il "perché", non solo il "cosa".
